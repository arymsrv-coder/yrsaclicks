## 1. What this site is

**yrsaclicks** is a one-purpose funnel site for an adventure photographer / model. Its job is to take traffic from an Instagram bio link, present a short cinematic opening, and hand the visitor to a paid OnlyFans destination behind a self-declared 18+ age confirmation.

**The real audience is not a desktop browser.** It is Instagram's in-app webview (Meta `WKWebView` on iOS, Android System WebView on Android) on a mid-to-low-tier phone, over cellular, with a cache that is cleared aggressively between visits. Nearly every decision in this codebase — the `dvh` fallbacks, the `@supports` guards, the transform-instead-of-mask aperture, the plain `<a>` on the gate's Continue button — exists because of that environment. **Any change that is only tested in desktop Chrome has not been tested.**

### 2.2 Build configuration — `next.config.ts`

```ts

basePath: process.env.NEXT_PUBLIC_BASE_PATH ?? ""
trailingSlash: true     // /members -> /members/index.html
images: { unoptimized: true }   // required by output:"export"
```

**Two consequences you must internalise:**

1. **`next/image` does nothing here.** No WebP/AVIF, no `srcset`, no resizing. `quality` and `sizes` props are silently inert. Verified: the built `out/index.html` contains **zero** `srcset` attributes. Images must be optimised at authoring time, before they enter `public/`.
2. **Every asset URL must go through `asset()`.** `next/link` applies `basePath` on its own; nothing else does — not `<video src>`, not `<link href>`, not CSS `url()`, not `next/image`'s `src`. See `app/lib/asset.ts:21`. Writing a literal `/media/...` path anywhere will 404 on the GitHub Pages deploy.

## 4. Design system

### 4.1 Colour tokens — `app/globals.css:7–38`

| Token | Value | Role |
|---|---|---|
| `--color-ink` | `#2e3b31` | Dark green. The brand ground: loader, footer, panels, page background. |
| `--color-paper` | `#ede7dd` | Off-white. The other half of the two-tone system; nearly all type. |
| `--color-pine-light` | `#9caf88` | Eyebrow accent **on ink** — 4.97:1 |
| `--color-maroon` | `#5a2a1f` | Eyebrow accent **on paper** — 9.55:1 |
| `--color-brass` | `#7a5a2c` | Filled-button ground. Darkened from `#8a6a3a` so paper-on-brass clears 4.5:1 (5.14:1). |
| `--color-bone` | `#e3dac9` | Button outline — warmer/deeper than paper so the edge separates from paper type inside it |
| `--color-gray` `--color-lavender` | `#8a8a8a` `#c4c4d4` | Legacy accents |
| `--color-bg-a` / `-text-a` / `-bg-b` / `-text-b` | aliases | Legacy, a few utilities still read them |

**Rule:** two accents exist because **no single accent clears 4.5:1 against both halves of the two-tone system.** Pick by ground, never by preference.

### 4.2 Typography

One family: **Montserrat**, `--font-body`, weights 400/500/600/700/800. The mark carries the character; the type stays neutral behind it. House idioms: `uppercase`, wide `tracking` (`0.12em`–`0.35em`) for small labels, tight negative tracking (`-0.02em`) for large display type, `leading-[0.9]`–`[0.95]` on headlines.

### 4.3 Motion vocabulary — `app/lib/motion.ts`

| Constant | Value | Use |
|---|---|---|
| `EASE` | `[0.83, 0, 0.17, 1]` (easeInOutQuint) | The signature curve. Everything that opens, closes, rises, settles. |
| `EASE_OUT` | `[0.19, 1, 0.22, 1]` (easeOutExpo) | Hover rolls, arrivals. |
| `LOAD_MS` | `4000` | Counter run time + reel window |
| `APERTURE_SHUT` | `50` | Panel fully closed |
| `APERTURE_STEPS` | `t:[0,.38,.62,1]` `x:[50,25,5,0]` `y:[50,35,35,0]` | The three-step opening |
| `APERTURE_S` | `1.9` | Loader aperture duration |
| `ZOOM_S` | `1.7` (in `Loader.tsx:50`) | Frame-to-fullscreen growth |

**The aperture is the site's one gesture.** Four half-panel bands, one per edge, opposite edges locked. Two numbers: `sy` drives top/bottom, `sx` drives left/right. The two axes are **deliberately out of step** — horizontal opens further and earlier — so the hole widens into a letterbox before it opens out. A symmetric version reads as a growing rectangle and loses the whole character.

Because the same keyframes are consumed by the loader (on a clock) and by `StackSection` (scrubbed by scroll), *"the loading screen and the scroll are the same animation"* is literally true, not a metaphor. Scrolling back up closes it with identical motion for free.

### 4.4 z-index scale — documented at `app/globals.css:3–5`

```
150  nav header
250  age-gate overlay
260  members header (above the gate)
270  members arrival veil   ← origin/main only
300  boot loader (above everything)
```

**Put new fixed/sticky layers on this scale.** Do not invent a number.

### 4.5 Defensive CSS — the low-end-webview guards

Three patterns exist because of the target environment. **Preserve them in any refactor.**

1. **`dvh` fallback (`globals.css:65–101`).** On browsers predating `dvh` (older Android WebViews, in-app engines), an unsupported value doesn't degrade — the *entire declaration is dropped*, so containers collapsed to zero height and took the animations with them. An `@supports not (height: 100dvh)` block restates each `dvh` utility in `vh`. **If you add a new `dvh` utility class, you must add it to this block by hand.**
2. **`.track-height` (`globals.css:103–114`).** The track height is set via a **unitless custom property** `--track-vh`, then read back as `calc(var(--track-vh) * 1vh)`, upgraded to `svh` inside `@supports`. A custom property's value is never parsed, so it can't be dropped as invalid the way a literal `Xsvh` string would be.
3. **`svh` vs `dvh` is a real distinction here.** The *plate* uses `dvh` (should always be full-bleed as the toolbar slides). The *track* uses `svh` (its height **is** the scroll distance — a relayout mid-scroll would jump the scrub).

## 5. Runtime walkthrough

### 5.1 Homepage load, frame by frame

1. **`ScrollProvider` mounts** (`app/page.tsx:77`). Creates a Lenis instance bound to a `fixed inset-0 overflow-y-auto` wrapper — **the page does not scroll the window, it scrolls a div.** Everything measuring scroll passes `container: containerRef`. Wraps children in `<MotionConfig reducedMotion="user">`.
2. **`Loader` takes the screen** at `z-[300]`, calls `lenis.stop()`.
3. **The reel plays.** Nine stills, each opening via `clipPath` out of the one before — no cuts, no cross-fades, successive openings. `STEP = LOAD_MS/1000/10 = 0.4 s`; each iris runs `0.4 × 1.4 = 0.56 s`, so a frame is still opening as the next begins.
4. **A counter runs 0 → 100** at the foot over `LOAD_MS = 4000 ms`.
5. **The tenth frame is `hero.mp4` itself.** So the last thing on screen is already the landing page's footage.
6. **At 100:** `onDone()` fires → header and hero text begin revealing *while the frame is still growing*. `measureZoom()` reads the frame's rect **and the panel's rect** (asking the element, not `window.innerHeight`, because `dvh` ≠ `innerHeight` when a mobile toolbar is out) and computes the exact `scale`/`x`/`y` to cover the viewport.
7. **The frame grows** over `ZOOM_S = 1.7 s`. Wordmark and counter fade out so the last thing moving is footage.
8. **On animation complete:** `close()` → `onHandoff(reelVideo.currentTime)` → `setOpen(false)`. The panel unmounts, `lenis.start()`.
9. **`Hero` picks the video up at `startAt % duration`** and only then calls `play()`. It deliberately does **not** autoplay from page load — that used to run two decoders of the same file out of step, and the hand-off landed on a 3.5-second jump cut.
10. **The scroll cue** (`Hero.tsx:109–152`) fades out over the first 220 px of scroll — driven off scroll *distance* with an explicit clamp, not normalised progress, because progress-mapping produced a V (faded out, then back in under the members plate).
11. **Scrolling reveals `StackSection`.** The plate rides up one viewport as a solid ink panel, holds a beat, then the aperture eats the panel away from the centre outward. Title → CTA → subtitle reveal in sequence.
12. **"Continue" → `/members`.**

**Total enforced wait before the site is visible: 4000 + 1700 = 5.7 s** (reduced motion collapses this to a single frame).

### 5.2 `/members` — ⚠️ two different implementations

| | **local `HEAD`** | **`origin/main` (deployed)** |
|---|---|---|
| Behind the gate | A "being prepared" holding page | **Nothing.** The gate *is* the page. |
| Age state | `sessionStorage` flag via `ageVerification.ts` + `useSyncExternalStore` | **No state at all.** File deleted. |
| Continue button | `<button>` → `markVerified()` → reveals holding page | **`<a href={checked ? OF_URL : undefined}>`** → leaves for OnlyFans, same tab |
| Background | Flat ink | Full-bleed `members.jpg`, `object-[center_22%]`, 2% neutral veil, `plate-arrive` CSS entrance |
| Gate veil | Inline `color-mix(ink 96%)` | `.gate-veil` class — `ink 38%` + `backdrop-filter: blur(6px)`, with an `@supports not` fallback back to `ink 92%` |
| Arrival | none | `.arrival-veil` — an opaque ink layer that clears on a **CSS keyframe**, deliberately not a motion component, so it doesn't hold a blank green screen while JS loads on a cheap phone |

**The remote design reasoning is worth preserving verbatim** (`app/members/page.tsx:14–33` on `origin/main`): the site *ends* at the gate. There is nothing behind it to unlock, so there is no flag to store. A stored confirmation would mean a returning visitor arrives at a satisfied gate with nothing behind it — a blank plate and no way forward.

And on the Continue anchor (`AgeGate.tsx:19–26`, `:118–127` on `origin/main`):
> *"a plain anchor is the one thing that survives Instagram's in-app browser — `window.open` there is either swallowed or treated as a popup, and a scripted navigation loses the user gesture."*

Until the checkbox is ticked the anchor carries **no `href` at all**, which makes it simultaneously un-clickable and un-focusable — and the hand-rolled focus trap already filters on `a[href]`, so the two mechanisms agree without extra code.

**This is the correct design and it must not be regressed.** §7 builds on the remote version, not the local one.

### T6 — The Instagram-webview nudge

**Scope: the OnlyFans link only.** Not site-wide, not on the hero, not on the legitimacy pages.

```ts
const isMetaWebview = () =>
  typeof navigator !== "undefined" &&
  /Instagram|FBAN|FBAV/i.test(navigator.userAgent);
```
Read it through `useSyncExternalStore` or a mount effect — **never branch on it during render**, or the server HTML and the hydrating client will disagree. `app/lib/useReducedMotionSafe.ts` is the exact pattern to copy (and if T1 deleted it, its docblock explains why the pattern is necessary).

- Style: `--color-pine-light` on the ink panel (4.97:1, the correct accent for this ground), small uppercase, wide tracking. Subordinate to the Continue button.
- Outside the Meta webview: render nothing at all. No placeholder, no reserved space.

**Hard constraints — non-negotiable:**
- 🚫 **No forced redirect. No `window.location` manipulation. No auto-open. No `window.open`.** The "Ali Browser" pattern was explicitly rejected as a platform-policy risk (§6.E4).
- The Continue anchor stays exactly as it is: a plain `<a>`, same tab, `href` present only when the box is ticked. **Do not convert it to a button or add a click handler** — `AgeGate.tsx:19–26` explains that a plain anchor is the one navigation that survives Instagram's webview, because `window.open` there is swallowed or popup-blocked and a scripted navigation loses the user gesture.

**Done when:** the hint appears with a spoofed `Instagram` UA and not with a stock Safari/Chrome UA; the Continue link navigates identically in both cases; dismissing hides it without affecting the link; the focus trap still cycles; no hydration warning in the console.

### Regression traps

Ranked by how likely they are to be tripped:

1. **Writing a literal `/media/...` path** instead of `asset()`. Works locally, 404s on the Pages deploy.
2. **Adding a `dvh` utility without adding it to the `@supports not` block** in `globals.css:65–101`. The element silently collapses to zero on old Android WebViews.
3. **Losing `<MotionConfig reducedMotion="user">`** during T1 — it lives inside the provider being deleted.
4. **Branching on `matchMedia` or `navigator.userAgent` during render.** Server and client disagree; React refuses to patch it. Use `useSyncExternalStore` (`useReducedMotionSafe.ts` is the reference).
5. **Converting the gate's Continue anchor to a button.** Breaks the one navigation that survives Instagram's webview.
6. **Introducing a redirect or `window.location` hijack.** Explicitly rejected on platform-policy grounds.
7. **Picking an arbitrary z-index** instead of extending the documented scale.
8. **Trusting `Notes/deployment-weight-and-webview-performance.md`'s numbers.** Stale since 2026-08-11 — see §2.5.
9. **Trusting `docs/superpowers/specs/2026-08-25-single-button-flow-design.md`'s "current state".** Written against a tree 8 commits behind the deploy.
